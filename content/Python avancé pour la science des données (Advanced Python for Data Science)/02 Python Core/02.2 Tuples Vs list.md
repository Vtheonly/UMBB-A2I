---

### **Tuples vs. Lists: The Decision Guide**

In your provided notes (Chapter 3, Slide 1 & 7), the core definition defines the rule:

*   **List (`[]`):** Mutable (Can be changed after creation).
*   **Tuple (`()`):** **Immutable** (Cannot be changed after creation).

### **Case 1: Storing a Fixed "Record" of Data**
**Context:** *Tutorial 03 - Exercise 2: Parse Products Function*

In this exercise, you were asked to write a function that converts a text line into a tuple:
> **Task:** "Converts each line into a tuple (name, price, quantity)"
> **Output:** `[("Laptop", 1000.0, 3), ("Phone", 500.0, 5)]`

**Why use a Tuple here?**
You have a list of products. The **List** is used for the collection because you might want to add more products later (using `.append()`).

However, the **Product itself** (the inner part) is a specific set of 3 items that belong together.
*   **Structure Integrity:** A product *must* have exactly a Name, a Price, and a Quantity. Using a tuple locks these three values together.
*   **Prevention of Accidental Change:** You don't want a bug in your code to accidentally delete the "Price" from a product while keeping the Name and Quantity. Since tuples are immutable, Python forbids you from doing `product[1] = 500` or `del product[2]`. To change a product, you must replace the whole tuple.

### **Case 2: Fixed Configuration or Dimensions**
**Context:** *Chapter 3 - Slide 7 (Tuples)*

The slides provide this specific example:
```python
dimensions = (1920, 1080)
```

**Why use a Tuple here?**
*   **Semantic Meaning:** These two numbers represent a single concept (Screen Resolution). They are not just a list of random numbers; they are a pair.
*   **Safety:** Screen dimensions shouldn't change during the program's execution. If you used a list `[1920, 1080]`, you (or another programmer) could accidentally write `dimensions.append(50)`, which would break any code expecting exactly width and height. A tuple makes this impossible.

### **Case 3: Dictionary Keys**
**Context:** *Chapter 3 - Slide 7 (Dictionaries)*

The slides state:
> "Keys must be unique and **immutable** (string, number, **tuple**)."

**Why use a Tuple here?**
If you wanted to store data based on coordinate locations (like a grid), you **cannot** use a list as a dictionary key because lists can change. You **must** use a tuple.

```python
# CORRECT
locations = {
    (36.7, 3.0): "Alger",   # Tuple as key
    (35.6, 0.6): "Oran"
}

# INCORRECT (Will Crash)
locations = {
    [36.7, 3.0]: "Alger"    # List as key -> TypeError: unhashable type: 'list'
}
```

### **Summary Table**

| Feature | List `[]` | Tuple `()` | Context Example |
| :--- | :--- | :--- | :--- |
| **Mutability** | **Changeable** (Add, remove, update items) | **Unchangeable** (Locked once created) | Ch 3, Slide 7 |
| **Best For** | Collections of similar items that grow/shrink | Fixed records, coordinates, or configurations | Tutorial 3 (Products) |
| **Performance** | Slower (Overhead for being changeable) | Faster (Python optimizes them) | Ch 3 (Implied) |
| **Dict Keys** | ❌ Cannot be used as keys | ✅ Can be used as keys | Ch 3, Slide 7 |
