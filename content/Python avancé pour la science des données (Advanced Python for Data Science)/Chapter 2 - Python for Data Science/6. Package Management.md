# 6. Package Management: pip vs. conda

In Data Science, we don't just use Python code; we use "packages" (libraries) written by others. We need tools to download and manage these.

## 6.1 pip vs. conda: The Comparison

| Feature | **pip** (Python Package Installer) | **conda** |
| :--- | :--- | :--- |
| **Scope** | Python libraries only. | Any language (Python, R, C, etc.). |
| **Source** | PyPI (Python Package Index). | Anaconda repositories & Conda-forge. |
| **Dependencies** | Can sometimes cause conflicts. | Advanced solver checks for compatibility. |
| **Environments** | Does not manage environments (uses `venv` tool). | Built-in environment management. |
| **Best Use** | General Python dev. | Data Science / Scientific Computing. |

### Best Practices
*   **Use `conda` inside Anaconda:** It handles complex binary dependencies (common in science libraries) much better.
*   **Use `pip` as a fallback:** If a library isn't available in conda, you can use pip *inside* your conda environment.

## 6.2 Managing Libraries

### A. Using `pip`

**Installation:**
```bash
pip install numpy pandas          # Install multiple
pip install pandas==1.5.3         # Install specific version
pip install --upgrade matplotlib  # Upgrade
pip uninstall seaborn             # Remove
```

**Sharing Environments (Freezing):**
To let someone else run your code, you need to give them a list of your libraries.
1.  **Save list:** `pip freeze > requirements.txt`
2.  **Install list (on other machine):** `pip install -r requirements.txt`

### B. Using `conda`

**Installation:**
```bash
conda install numpy pandas
```

**Using Channels (`conda-forge`):**
Sometimes the default Anaconda channel doesn't have a specific package. `conda-forge` is a community-driven collection of recipes.
```bash
conda install -c conda-forge seaborn
```

**Sharing Environments:**
1.  **Export:** `conda env export > environment.yml`
2.  **Recreate:** `conda env create -f environment.yml`
