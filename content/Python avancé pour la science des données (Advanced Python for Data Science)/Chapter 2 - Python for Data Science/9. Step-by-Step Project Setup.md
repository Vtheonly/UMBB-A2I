# 9. Practical Scenario: Setting Up a Data Science Project

This guide combines all the concepts into a real-world workflow. Follow these steps when starting a new project.

## Step 1: Create Project Folder
Create a clean directory for your work.
```bash
mkdir MYProject
cd MYProject
```

## Step 2: Set Up a Virtual Environment
Isolate your dependencies immediately.

**Using Conda (Recommended):**
```bash
conda create -n myenv python=3.10
conda activate myenv
```
*   *Note:* `myenv` is the name of your environment. You can name it whatever you like.

## Step 3: Install Your Libraries
Install the Data Science stack.
```bash
pip install numpy pandas matplotlib seaborn scikit-learn jupyter
```
*   *Why pip here?* Sometimes even in Conda environments, people use pip commands. However, `conda install ...` is preferred if available.

## Step 4: Freeze Your Environment
Create a record of your installed packages so others (or you in the future) can replicate this setup.
```bash
pip freeze > requirements.txt
# OR if using Conda specific export
conda env export > environment.yml
```

## Step 5: Initialize Git
Start version control.
```bash
git init
```
**Important:** create a `.gitignore` file to stop git from tracking your virtual environment folder or garbage files.
```bash
echo "env/" >> .gitignore
echo "__pycache__/" >> .gitignore
echo ".ipynb_checkpoints/" >> .gitignore
```
Then commit your initial setup:
```bash
git add .
git commit -m "Initial setup"
```

## Step 6: Create Folder Structure
Set up the professional file tree.
```text
MYProject/
│
├── data/               # Raw and processed data
├── notebooks/          # Jupyter notebooks for exploration
├── src/                # Python scripts (cleaning, modeling)
├── outputs/            # Plots, charts, reports
├── requirements.txt    # Dependency file
└── README.md           # Project documentation
```

## 8. Best Practices Summary
1.  **One environment per project:** Don't reuse a "global" environment for everything.
2.  **Track dependencies:** Always update your `requirements.txt`.
3.  **Git from the start:** Run `git init` before you write a single line of code.
4.  **Separate Data:** Keep `raw` data separate from `processed` data.
5.  **Use `.gitignore`:** Never commit large datasets or virtual environment folders to Git.
6.  **Pin Versions:** Use specific versions (e.g., `pandas==1.5`) if reliability is critical.
