# 5. Virtual Environments in Python

A **virtual environment** is a self-contained directory tree that contains a Python installation for a particular version of Python, plus a number of additional packages.

## 5.1 Why do we need them?
Imagine Project A needs `pandas` version 1.0, but Project B needs `pandas` version 2.0. If you install everything globally on your computer, you can only have one version. **Dependency Hell** ensues.

**Benefits:**
1.  **Isolation:** Project dependencies do not interfere with each other.
2.  **Reproducibility:** You can generate a list of exact library versions so others can run your code.
3.  **Safety:** You won't break your system-level Python installation.

## 5.2 Creating Environments: `venv` vs `conda`

### Option A: Using `venv` (Built-in Standard)
Best for general Python development.

1.  **Create:**
    ```bash
    python -m venv myenv
    ```
2.  **Activate:**
    *   **Windows:** `.\myenv\Scripts\activate`
    *   **Mac/Linux:** `source myenv/bin/activate`
    *   *Note:* You will see `(myenv)` appear in your terminal prompt.
3.  **Install Libraries:**
    ```bash
    pip install pandas numpy matplotlib
    ```
4.  **Deactivate:**
    ```bash
    deactivate
    ```

### Option B: Using `conda` (Recommended for Data Science)
Best if you are using Anaconda. Conda environments are more powerful because they can handle non-Python library dependencies.

1.  **Create:**
    ```bash
    conda create --name ds_env python=3.11
    ```
2.  **Activate:**
    ```bash
    conda activate ds_env
    ```
3.  **Install Libraries:**
    ```bash
    conda install pandas numpy matplotlib scikit-learn
    ```
4.  **List Environments:**
    ```bash
    conda env list
    ```
