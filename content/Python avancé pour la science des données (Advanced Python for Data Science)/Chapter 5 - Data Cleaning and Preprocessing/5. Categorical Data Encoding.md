# 5. Categorical Data Encoding

## The Problem
Machine Learning models (like Linear Regression, Neural Networks) are mathematical functions. They cannot process text like "Red" or "Blue". We must convert these categories into numbers.

---

## 1. Label Encoding
*   **Method:** Assigns a unique integer to each category arbitrarily (e.g., Apple=0, Banana=1, Cat=2).
*   **Use Case:** strictly for **Ordinal Data** (Binary categories like Yes/No, Male/Female are also okay).
*   **The Trap:** If used on **Nominal Data** (no order), the model might misinterpret the numbers.
    *   If Paris=1 and Tokyo=10, the model thinks Tokyo is "greater than" or "10x more" than Paris. This is false.

## 2. Ordinal Encoding
*   **Method:** Explicitly mapping categories to numbers based on a logical order.
*   **Use Case:** **Ordinal Data** (Data with inherent rank).
*   **Example:**
    *   Low -> 0
    *   Medium -> 1
    *   High -> 2
*   **Code:** `df['Level'].map({'Low':0, 'Medium':1, 'High':2})`

## 3. One-Hot Encoding (OHE)
*   **Method:** Creates a new binary (0 or 1) column for *every* unique category.
*   **Example:** Column `Color` becomes `Color_Red`, `Color_Blue`, `Color_Green`.
*   **Use Case:** **Nominal Data** (Categories with no order, e.g., Country, Animal).
*   **Pros:** Prevents the model from assuming false ordinal relationships.
*   **Cons:** **Curse of Dimensionality**. If you have a column with 10,000 unique cities, OHE creates 10,000 new columns, making the dataset huge and slow.

## 4. Frequency Encoding
*   **Method:** Replaces the category with the count or frequency of its appearance in the dataset.
*   **Use Case:** High cardinality nominal data (e.g., Zip Codes, Product IDs) where OHE creates too many columns.
*   **Logic:** "London" appears 500 times -> Replace "London" with 500.

---

## Summary Decision Table

| Data Type | Example | Recommended Encoding |
| :--- | :--- | :--- |
| **Ordinal** | Sizes (S, M, L), Ratings (Bad, Good, Excellent) | **Ordinal / Label Encoding** |
| **Nominal (Low Cardinality)** | Gender (M, F), Continent (Asia, Europe) | **One-Hot Encoding** |
| **Nominal (High Cardinality)** | Zip Code, UserID, City (if many) | **Frequency Encoding** |
