# 4. Text Data Processing

## Overview
Text data (strings) is naturally messy. Before it can be analyzed or converted to categories, it must be normalized. Inconsistencies like "Paris", "paris ", and "PARIS" are treated as three distinct values by computers, which ruins analysis.

---

## Common Cleaning Steps

### 1. Casing (Lowercasing)
Converting everything to lowercase ensures uniformity.
*   `df['City'] = df['City'].str.lower()`

### 2. Whitespace Removal
Users often accidentally add spaces at the start or end of inputs. " New York" $\neq$ "New York".
*   `df['City'] = df['City'].str.strip()`

### 3. Special Character Removal
Removing punctuation or symbols that don't add value (e.g., "#London!" -> "London").
*   **Regex (Regular Expressions):** A powerful tool for pattern matching.
*   Code: `df['City'].str.replace(r'[^a-zA-Z\s]', '', regex=True)`
    *   `^a-zA-Z\s`: Keep only letters and spaces.
    *   Everything else is replaced with empty string.

### 4. Accent Removal (Unicode Normalization)
Crucial for international data. "München" vs "Munchen" vs "São Paulo".
*   Library: `unidecode`
*   Code: `df['City'].apply(lambda x: unidecode(x))`
    *   Converts "São Paulo" -> "Sao Paulo".

---

## Example Workflow
```python
# Raw: [" New York ", "paris", "München!", "PARIS"]

# 1. Lowercase
# -> [" new york ", "paris", "münchen!", "paris"]

# 2. Strip Whitespace
# -> ["new york", "paris", "münchen!", "paris"]

# 3. Remove Special Chars & Accents
# -> ["new york", "paris", "munchen", "paris"]
```
Now the computer correctly identifies that there are 3 unique cities, not 4.
