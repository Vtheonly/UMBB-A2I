# 2. Data Consistency and Duplicates

## 1. Ensuring Consistent Data Types
In Python (pandas), data types (`dtypes`) often default to `object` (string) if the raw data contained even a single error or symbol.

### Why it Matters
1.  **Memory:** `object` types consume significantly more RAM than `int` or `float`.
2.  **Functionality:** You cannot perform math (`sum`, `mean`) on strings. `"100" + "100"` results in `"100100"`, not `200`.
3.  **Modeling:** Machine Learning algorithms require numeric inputs.

### Common Conversions
| From | To | Method | Note |
| :--- | :--- | :--- | :--- |
| String ("100") | Integer/Float | `pd.to_numeric(df['col'], errors='coerce')` | `errors='coerce'` turns invalid text (like "Unable") into `NaN` (missing), preventing crashes. |
| String ("2024-01-01") | DateTime | `pd.to_datetime(df['col'])` | Unlocks time features like `.dt.year`, `.dt.month`. |
| Integer (1, 2) | Category | `.astype('category')` | Saves memory if the column has low cardinality (few unique values like "Low", "Med", "High"). |

> [!WARNING] **The `Object` Trap**
> Always check `df.info()` immediately after loading data. If a column looks like numbers but lists as `Dtype: object`, there is likely a hidden character or typo in one of the rows.

## 2. Handling Duplicates
Duplicate records can arise from merging datasets from different sources, system logging errors, or repeated manual entry.

### Why Duplicates are Dangerous
*   **Bias:** If a specific class (e.g., "Fraud") is duplicated 10 times, the model will overfit to those specific examples.
*   **Inflated Statistics:** Counts, sums, and averages will be incorrect.
*   **Data Leakage:** If you split data into Train/Test sets *before* removing duplicates, the same data point might appear in both, causing the model to "memorize" the answer rather than learn.

### Types of Duplicates
1.  **Exact Match:** Every column is identical.
2.  **Subset Match:** The unique identifier (e.g., `UserID`) is the same, but other columns (e.g., `Timestamp`) might differ slightly. You usually keep the most recent one.

### Handling Strategy (Python)

**1. Detection:**
```python
# Returns True for duplicated rows
duplicates = df.duplicated() 
print(duplicates.sum())
```

**2. Removal:**
```python
# Remove exact duplicates
df = df.drop_duplicates()

# Remove duplicates based on specific ID, keeping the first occurrence
df = df.drop_duplicates(subset=['UserID', 'Email'], keep='first')
```

> Sometimes duplicates aren't exact (e.g., "John Smith" vs "John  Smith " with extra space). These require **Text Normalization** (see Note 4) before duplicate detection works.
