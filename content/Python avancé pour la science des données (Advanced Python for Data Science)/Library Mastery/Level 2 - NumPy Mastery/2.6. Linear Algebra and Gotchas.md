
# 2.6. Linear Algebra and Gotchas

## 1. Linear Algebra Toolkit (`np.linalg`)

Since NumPy is the foundation for Machine Learning, its Linear Algebra engine is heavily optimized.

| Function | Description |
| :--- | :--- |
| **`np.dot(A, B)`** / **`@`** | Matrix Multiplication (Dot Product). Inner dimensions must match. |
| **`np.trace(A)`** | Sum of the diagonal elements. |
| **`arr.T`** | Transpose of the matrix. |
| **`np.linalg.det(A)`** | Determinant of the matrix. |
| **`np.linalg.inv(A)`** | Inverse of the matrix. |
| **`np.linalg.solve(A, b)`** | Solves for $x$ in the linear system $Ax = b$. |
| **`np.linalg.norm(A)`** | Magnitude (Vector Norm). |
| **`np.linalg.eig(A)`** | Eigenvalues and Eigenvectors. |

## 2. NumPy Pitfalls and "Gotchas"

Even experienced developers fall into these traps:

1. **Missing Data Casts to Float:** 
   `np.nan` (Not a Number) is technically a float type in Python. If you insert `np.nan` into an integer array, **the entire array is upcast to float**.
2. **Boolean Logic Errors:**
   `arr[arr > 5 and arr < 10]` will crash. You must use Bitwise operators with parentheses: `arr[(arr > 5) & (arr < 10)]`.
3. **Unexpected Mutation (Views):**
   `b = a` does not create a new array; it creates a pointer. `b = a[0:2]` creates a view. Modifying `b` will permanently modify `a`. Always use `.copy()` for safety.
4. **0-Indexing:**
   `arr[5]` selects the **6th** element, not the 5th.
