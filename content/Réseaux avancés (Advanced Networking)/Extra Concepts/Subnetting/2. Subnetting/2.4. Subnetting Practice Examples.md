# 2.4. Subnetting Practice Examples

## 1. Introduction
The key to mastering subnetting is practice. This note provides additional worked-out examples, including two straightforward cases and two that introduce common "tricky" scenarios you might encounter on an exam or in the real world.

We will use the same 7-step process demonstrated in the previous note.

- **Cheat Sheet Reference:**


| Group Size | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **Subnet Mask**| 128 | 192 | 224 | 240 | 248 | 252 | 254 | 255 |
| **CIDR** | /25 | /26 | /27 | /28 | /29 | /30 | /31 | /32 |

## 2. Standard Example 1: 10.2.2.88 /27

1.  **CIDR:** `/27`
2.  **Cheat Sheet:** Group Size is `32`, Mask is `255.255.255.224`.
3.  **List Network IDs (increments of 32) until we pass 88:**
    `0, 32, 64, 96`
4.  **Box the Range:** The target IP `.88` is between `64` and `96`.
5.  **Identify IDs:**
    -   Network ID: `10.2.2.64`
    -   Next Network: `10.2.2.96`
    -   Broadcast IP: `10.2.2.95` (`.96 - 1`)
6.  **Calculate Host IPs:**
    -   First Host IP: `10.2.2.65`
    -   Last Host IP: `10.2.2.94`
7.  **Number of IPs:**
    -   Total: 32 / Usable: 30

## 4. Tricky Example 1: The IP is the Network ID

Sometimes, the IP address you're given isn't a host address but is actually the Network ID of the subnet. The process remains the same, but you must follow the rules carefully.

**Problem:** `10.2.2.20 /30`

1.  **CIDR:** `/30`
2.  **Cheat Sheet:** Group Size is `4`, Mask is `255.255.255.252`.
3.  **List Network IDs (increments of 4) until we pass 20:**
    `0, 4, 8, 12, 16, 20, 24`

> **[>!WARNING] Common Pitfall**
> Students often stop at `20` because it matches the target IP. The rule is to list multiples until you **PASS** the target IP. You must include `24` in your list to correctly identify the "Next Network."

4.  **Box the Range:** Our target IP `.20` isn't *between* two numbers; it *is* one of the numbers. This tells us that the IP address `10.2.2.20` is the Network ID for this subnet. The "box" is effectively `20` and `24`.

5.  **Identify IDs:**
    -   **Network ID:** `10.2.2.20` (The IP itself)
    -   **Next Network:** `10.2.2.24`
    -   **Broadcast IP:** `10.2.2.23` (`.24 - 1`)
6.  **Calculate Host IPs:**
    -   First Host IP: `10.2.2.21`
    -   Last Host IP: `10.2.2.22`
7.  **Number of IPs:**
    -   Total: 4 / Usable: 2

**Key Takeaway:** If your target IP matches one of the increments, it is the Network ID. Always go one increment *past* your target to find the Next Network.

## 5. Tricky Example 2: Crossing Octet Boundaries

What happens when your increments go past 255? You can't have `256` in an octet. The increment "rolls over" to the next octet, just like counting from 99 to 100 in decimal.

**Problem:** `10.2.2.199 /26`

1.  **CIDR:** `/26`
2.  **Cheat Sheet:** Group Size is `64`, Mask is `255.255.255.192`.
3.  **List Network IDs (increments of 64) until we pass 199:**
    `0, 64, 128, 192, 256`

> **[>!WARNING] Invalid IP Value**
> The value `256` is not a valid octet value. The maximum is `255`. When an increment would result in `256`, it means the fourth octet resets to `0` and the third octet increments by `1`.

4.  **Rewriting the Network IDs with full IPs:**
    - `10.2.2.0`
    - `10.2.2.64`
    - `10.2.2.128`
    - `10.2.2.192`
    - `10.2.3.0` (This is our `256` rollover)

5.  **Box the Range:** Our target IP `10.2.2.199` is between `10.2.2.192` and `10.2.3.0`.

6.  **Identify IDs:**
    -   **Network ID:** `10.2.2.192`
    -   **Next Network:** `10.2.3.0`
    -   **Broadcast IP:** The IP address right before `10.2.3.0` is `10.2.2.255`.
7.  **Calculate Host IPs:**
    -   First Host IP: `10.2.2.193`
    -   Last Host IP: `10.2.2.254`
8.  **Number of IPs:**
    -   Total: 64 / Usable: 62

**Key Takeaway:** When listing increments, if you reach `256`, change it to `.0` and increment the next octet to the left by one. This is how you correctly identify the boundaries of subnets at the edge of an octet.
