# 3.2. Fixed-Length Subnet Mask (FLSM)

## 1. Understanding FLSM Logic
Fixed-Length Subnet Mask (FLSM) is a method where a network is divided into multiple subnets that are all the same size. The core logic behind solving FLSM problems is understanding the relationship between the number of subnets you create and the size of those subnets.

**The Golden Rule:** Every time you increment the CIDR prefix by 1, you **double the number of networks** and **halve the size of each network**.

- Start with a `/22` (1024 IPs).
- Subnet it to `/23`. You now have two `/23` networks, each with 512 IPs.
- Subnet it further to `/24`. You now have four `/24` networks, each with 256 IPs.
- Subnet it again to `/25`. You now have eight `/25` networks, each with 128 IPs.

This "doubling effect" is the key to solving FLSM problems quickly.

---

## 2. The Powers of 2 Table
To solve these problems without manually counting, we can use a simple powers of 2 table. This is an essential tool for any network engineer.

| Power (n) | Result (2^n) |
| :---: | :---: |
| 0 | 1 |
| 1 | 2 |
| 2 | 4 |
| 3 | 8 |
| 4 | 16 |
| 5 | 32 |
| 6 | 64 |
| 7 | 128 |
| 8 | 256 |
| 9 | 512 |
| 10 | 1024 |

## 3. Type 1 FLSM Problem: Find the Subnet Size

This type of question gives you a starting network and asks what size subnets you need to create a certain number of networks.

**Problem:** You have the network `172.16.0.0/18`. What CIDR prefix is required to create at least **100 subnets**?

### Method 1: The Doubling Logic (Conceptual)
1.  **Start:** You have `1` network of size `/18`.
2.  Increment to `/19`: You get `2` networks.
3.  Increment to `/20`: You get `4` networks.
4.  Increment to `/21`: You get `8` networks.
5.  Increment to `/22`: You get `16` networks.
6.  Increment to `/23`: You get `32` networks.
7.  Increment to `/24`: You get `64` networks. (Still not enough for 100).
8.  Increment to `/25`: You get `128` networks. (This is enough!).

**Answer:** You need `/25` subnets.

### Method 2: The Powers of 2 Shortcut (Faster)
This method is much faster and less prone to counting errors.

1.  **Identify the Condition:** You need at least `100` subnets.
2.  **Use the Powers of 2 Table:** Look down the "Result" column for the first number that is greater than or equal to `100`.
    - The value is `128`.
3.  **Find the Corresponding Power:** `128` corresponds to a power of `7` (2^7).
4.  **Add the Power to the Starting CIDR:** The number `7` tells you how many times you need to increment the CIDR prefix.
    - `Starting CIDR + Power = Final CIDR`
    - `18 + 7 = 25`

**Answer:** `/25`

## 4. Type 2 FLSM Problem: Find the Number of Subnets

This type of question gives you a starting network and an ending subnet size, and asks how many subnets you can create.

**Problem:** You have the network `10.0.0.0/21`. How many `/26` subnets can you create from it?

### Method 1: The Doubling Logic (Conceptual)
1.  **Start:** You have `1` network of `/21`.
2.  `/22`: You get `2` networks.
3.  `/23`: You get `4` networks.
4.  `/24`: You get `8` networks.
5.  `/25`: You get `16` networks.
6.  `/26`: You get `32` networks.

**Answer:** You can create `32` subnets.

### Method 2: The Powers of 2 Shortcut (Faster)

1.  **Find the Difference in CIDR Prefixes:**
    - `Ending CIDR - Starting CIDR = Power (n)`
    - `26 - 21 = 5`
2.  **Calculate 2 to that Power:** The result is the number of subnets.
    - `2 ^ 5 = 32`

**Answer:** `32` subnets.

> [!TIP] A slightly more complex version of this question might give you a host requirement instead of a final CIDR.
> **Example:** "How many subnets containing at least 50 IPs can you create from a /21?"
> 1.  First, convert the host requirement to a CIDR prefix. To get 50 usable IPs, you need a total of 52 IPs. The smallest "Group Size" from our cheat sheet that fits 52 is `64`, which is a `/26`.
> 2.  Now the problem is the same as before: "How many /26s in a /21?"
> 3.  `26 - 21 = 5`. `2 ^ 5 = 32`.

---

## 5. Summary
FLSM problems are straightforward calculations that revolve around the powers of 2. By identifying the starting point, the ending point, and the condition, you can quickly solve for either the required subnet size or the number of available subnets. The shortcut methods using CIDR subtraction and the powers of 2 table are the most efficient ways to solve these questions.
