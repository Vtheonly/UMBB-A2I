# 4.2. Discontiguous Wildcard Masks

## 1. Beyond Standard Masks
In the previous note, we established that a standard wildcard mask is a perfect inverse of a subnet mask—a series of `0`s followed by a series of `1`s. This is great for matching a single, contiguous subnet.

However, the true power of wildcard masks lies in their ability to be **discontiguous**. This means the `0`s and `1`s in the mask can be interleaved in any pattern. This allows a single rule to match a set of IP addresses that do not fall neatly into one standard subnet.

- **Subnet Mask Rule:** Must be a contiguous block of `1`s followed by `0`s.
- **Wildcard Mask Rule:** No such rule. Any combination of `0`s and `1`s is valid.

A mask like `00001101.10100011...` is **invalid** as a subnet mask but **perfectly valid** as a wildcard mask.

## 2. The Core Principle: Bit-by-Bit Matching
The rule for a wildcard mask never changes, whether it's contiguous or not:
- **`0`**: The corresponding bit in the IP address **must match**.
- **`1`**: The corresponding bit in the IP address **does not matter** (it's a "wildcard" or "don't care" bit).

Let's see how this works in a practical scenario.

---

## 3. Scenario: Optimizing an Access Control List (ACL)

Imagine a company with several departments, each with a Data network and a Voice network.

- **IP Scheme:**
  - Support Data: `10.10.10.0/24`
  - Support Voice: `10.10.11.0/24`
  - Marketing Data: `10.10.20.0/24`
  - Marketing Voice: `10.10.21.0/24`
  - Operations Data: `10.10.66.0/24`
  - Operations Voice: `10.10.67.0/24`
  - Engineering Data: `10.10.90.0/24`
  - Engineering Voice: `10.10.91.0/24`

A standard ACL to permit traffic from all these networks would require **eight separate lines**:
```
access-list 10 permit 10.10.10.0 0.0.0.255
access-list 10 permit 10.10.11.0 0.0.0.255
access-list 10 permit 10.10.20.0 0.0.0.255
...and so on for all eight networks.
```
This is inefficient. A router has to process every packet against each line of the ACL sequentially. We can use a discontiguous wildcard mask to dramatically shorten this list.

---

## 4. Finding the Pattern: Binary Analysis

The key is to write the IP addresses in binary and look for patterns. We are most interested in the third octet, as the first two (`10.10`) are always the same and the last octet is always a wildcard (`.0` with mask `.255`).

| Network | 3rd Octet (Decimal) | 3rd Octet (Binary) |
| :--- | :---: | :---: |
| Support Data | 10 | `00001010` |
| Support Voice| 11 | `00001011` |
| Marketing Data | 20 | `00010100` |
| Marketing Voice| 21 | `00010101` |
| Ops Data | 66 | `01000010` |
| Ops Voice | 67 | `01000011` |
| Eng Data | 90 | `01011010` |
| Eng Voice | 91 | `01011011` |

Let's analyze the binary patterns bit by bit.

- **Bit 8 (far right):** This bit is `0` for all Data networks and `1` for all Voice networks.
- **Other bits:** The other bits vary between the different departments.

### Optimization 1: Combining Data and Voice
Notice that for any given department, the first 7 bits of the third octet are identical for the Data and Voice networks. Only the last bit changes.

- Support Data: `0000101`**`0`**
- Support Voice: `0000101`**`1`**

We can create a wildcard mask that checks the first 7 bits but ignores the last one.
- **Match bits:** `0000000`
- **Wildcard bit:** `1`
- **Wildcard Mask for 3rd Octet (Binary):** `00000001`
- **Wildcard Mask for 3rd Octet (Decimal):** `1`

Now we can combine each pair of entries into one:
- `access-list 10 permit 10.10.10.0 0.0.1.255` (Matches both 10.10.10.x and 10.10.11.x)
- `access-list 10 permit 10.10.20.0 0.0.1.255`
- `access-list 10 permit 10.10.66.0 0.0.1.255`
- `access-list 10 permit 10.10.90.0 0.0.1.255`

We've reduced our ACL from **8 lines to 4 lines**.

### Optimization 2: Finding More Patterns

Let's look at our four simplified binary patterns for the third octet (ignoring the last bit):
- Support: `0000101`
- Marketing: `0001010`
- Ops: `0100001`
- Engineering: `0101101`

Are there other bits we can ignore? Let's analyze the columns.
- **Bit 2 (from right):** Is `1` for Support/Ops, and `0` for Marketing/Eng.
- **Bit 5 (from right):** Is `1` for Marketing/Eng, and `0` for Support/Ops.
- **Bit 7 (from right):** Is `1` for Ops/Eng, and `0` for Support/Marketing.

This gets complicated quickly. However, a simpler observation is to find columns where **both `0` and `1` are present across the set of networks we want to match**. If a bit position sometimes needs to be `0` and sometimes needs to be `1`, we can use a wildcard (`1`) in our mask for that position.

Looking at the full binary of all 8 networks again:
- The last bit is sometimes `0`, sometimes `1` -> Mask bit should be `1`.
- The 2nd-to-last bit is sometimes `0`, sometimes `1` -> Mask bit should be `1`.
- The 4th-to-last bit is sometimes `0`, sometimes `1` -> Mask bit should be `1`.

By identifying all such "don't care" columns, we can create a single, highly optimized wildcard mask. Through careful analysis of the bits, we might find a single line that covers all eight networks.

For this specific, carefully chosen example, a possible solution is:
- **IP Address:** `10.10.0.0`
- **Wildcard Mask:** `0.0.255.255` (This is too broad)

A better, more precise mask can be crafted. Let's re-examine the third octet:
`0000101x`
`0001010x`
`0100001x`
`0101101x`

Let's make a composite mask. A `0` means all values in the column are identical. A `1` means they differ.
`x`: Last bit differs. MASK = 1
`1/0`: 2nd bit differs. MASK = 1
...and so on.
This process reveals the optimal mask to reduce the ACL to a single line. For this example, a clever mask like **`0.0.95.255`** used with address **`10.10.0.0`** might be engineered to match all of them, though this requires very careful planning.

---

## 5. Real-World Practicality

While discontiguous wildcard masks are a powerful tool and an important concept for certification exams, they are **rarely used in practice**.

- **Requires Strict IP Planning:** The network's IP addressing scheme must be meticulously designed around the binary patterns you want to match. This is often more trouble than it's worth.
- **Negligible Performance Gain:** Modern routers are so fast that the performance difference between processing an ACL with eight lines versus one line is virtually unnoticeable.
- **Readability and Maintenance:** An ACL with eight clear, simple lines is far easier for a human to read, troubleshoot, and maintain than one line with a complex, non-obvious binary mask.

**Recommendation:**
- Understand the *concept* for exams.
- In practice, use standard, contiguous wildcard masks that are easy to understand (`0.0.0.255`, `0.0.0.15`, etc.).
- Prioritize clarity and maintainability over micro-optimizations.
