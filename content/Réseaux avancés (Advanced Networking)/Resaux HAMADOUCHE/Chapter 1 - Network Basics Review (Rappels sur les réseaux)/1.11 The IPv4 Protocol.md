## 1. The PDU: The Packet (Datagram)
The IP Protocol (Layer 3) encapsulates the Transport Segment. It provides **unreliable, best-effort** delivery.

### Header Structure (Min 20 Bytes)
The header contains essential routing info. Read row by row (4 bytes / 32 bits wide).

| Field              | Bits | Function                                                                                |
| :----------------- | :--- | :-------------------------------------------------------------------------------------- |
| **Version**        | 4    | Usually `4` (for IPv4).                                                                 |
| **IHL**            | 4    | Internet Header Length. Min value is 5 (5 * 32-bit words = 20 Bytes).                   |
| **ToS**            | 8    | Type of Service (QoS, Priority).                                                        |
| **Total Length**   | 16   | Total size of packet (Header + Data). Max 65,535 bytes.                                 |
| **Identification** | 16   | ID used to reassemble fragmented packets.                                               |
| **Flags**          | 3    | `[Reserved, DF, MF]`. Control fragmentation.                                            |
| **Frag Offset**    | 13   | Where this fragment fits in the original packet.                                        |
| **TTL**            | 8    | **Time To Live**. Decremented by 1 at every router. If 0, packet dies (prevents loops). |
| **Protocol**       | 8    | What is inside? (TCP=6, UDP=17, ICMP=1).                                                |
| **Checksum**       | 16   | Error checking for the *Header only*.                                                   |
| **Source IP**      | 32   | The sender's IP.                                                                        |
| **Dest IP**        | 32   | The receiver's IP.                                                                      |

## 2. Fragmentation
Networks have a **MTU (Maximum Transmission Unit)**. For Ethernet, MTU is usually **1500 bytes**.
If a packet is larger than the MTU of the next link, the router must **fragment** it (slice it up), unless the **DF (Don't Fragment)** flag is set (in which case, the packet is dropped).

### Fragmentation Logic
1.  **Identification:** All fragments of the same original packet get the same ID.
2.  **MF (More Fragments) Flag:**
    *   Set to `1` for all fragments except the last one.
    *   Set to `0` for the last fragment.
3.  **Fragment Offset:** Indicates the position of the data. **Important:** The value is the number of **8-byte blocks**.
    *   *Real Offset in bytes = Field Value × 8*.

### Example (Slide 105)
*   **Packet:** 4000 bytes (20 Header + 3980 Data).
*   **MTU:** 1500 bytes.
*   **Max Data per Fragment:** $1500 - 20 = 1480$.
    *   *Note:* 1480 is divisible by 8, so it works.

**Calculation:**
1.  **Fragment 1:**
    *   Data: 0 to 1479 (1480 bytes).
    *   Offset: `0`.
    *   MF: `1`.
2.  **Fragment 2:**
    *   Data: 1480 to 2959 (1480 bytes).
    *   Offset: $1480 / 8 = 185$.
    *   MF: `1`.
3.  **Fragment 3:**
    *   Data: 2960 to 3979 (Remaining 1020 bytes).
    *   Offset: $(1480 + 1480) / 8 = 370$.
    *   MF: `0`.

> [!NOTE] **Reassembly**
> Routers fragment, but they **do not** reassemble. Reassembly happens only at the **Destination Host**. This saves router CPU.
