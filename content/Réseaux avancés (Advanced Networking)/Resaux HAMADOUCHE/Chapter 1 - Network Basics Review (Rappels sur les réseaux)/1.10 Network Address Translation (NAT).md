
## 1. The Problem
Private IP addresses cannot route on the Internet. If a device with IP `192.168.1.5` sends a packet to Google, Google cannot reply because `192.168.1.5` is not a valid destination on the public web.

## 2. The Solution: NAT
**NAT** allows a router (Gateway) to translate Private IPs into a Public IP before sending the packet to the Internet. It modifies the **IP Header** (Source IP for outgoing, Destination IP for incoming).

## 3. Types of NAT

### A. Static NAT (1-to-1)
*   **Definition:** Manually mapping **one** private IP to **one** specific public IP.
*   **Use Case:** Web Servers or Mail Servers inside a LAN that need to be accessible from the outside.
*   **Pros:** Bi-directional initiation (Internet can start connection to server).
*   **Cons:** Expensive (Need 1 Public IP per 1 Private Server).

### B. Dynamic NAT (Many-to-Many)
*   **Definition:** Mapping a group of private IPs to a **pool** of public IPs.
*   **Mechanism:** First come, first served. If the pool runs out, the next user cannot connect.
*   **Use Case:** Large corporate guest networks.

### C. PAT (Port Address Translation) / NAT Overload (Many-to-1)
*   **Definition:** Mapping **many** private IPs to a **single** public IP using different **Source Ports**.
*   **Mechanism:** The router uses the TCP/UDP Port number to track which internal device requested the data.
    *   *Internal:* `192.168.1.5:4095` -> *Translated:* `203.0.113.5:8001`
    *   *Internal:* `192.168.1.6:3022` -> *Translated:* `203.0.113.5:8002`
*   **Use Case:** Home networks, Small/Medium businesses. (This is what your home router does).
*   **Pros:** Saves massive amounts of Public IPs.

> [!TIP] **Security Benefit**
> NAT acts as a basic firewall. Since internal IPs are hidden, an attacker on the Internet cannot directly address or initiate a connection to a specific computer inside the LAN (unless Port Forwarding is configured).
