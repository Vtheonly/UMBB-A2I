
# 2.3. Route Aggregation (Summarization)

### **The Problem**
In large networks, routing tables can become massive.
*   **Consequences:** High RAM usage, slower CPU processing (longer lookup times), and increased bandwidth usage for routing updates.

### **The Solution: Aggregation**
**Route Aggregation** (or Supernetting) is the process of combining multiple specific subnet routes into a single, generic "summary" route.

*   **Principle:** Replace several entries with one "Super-route" that covers the entire range of IP addresses.

### **Step-by-Step Calculation**
To summarize routes, use binary alignment:

1.  **Write out the networks in binary.**
2.  **Find the common pattern** starting from the left (High Order Bits).
3.  **Count the matching bits**; this becomes your new Prefix Length (CIDR).
4.  **Set the remaining bits to 0**; this becomes the Summary Network Address.

**Example:**
We want to summarize these 4 networks:
*   `10.2.1.0/24`
*   `10.2.2.0/24`
*   `10.2.3.0/24`
*   `10.2.4.0/24` *(Note: The example in the slides (Slide 132) implies a summary that covers a block. If we summarize 1.0, 2.0, 3.0, 4.0, the binary math works as follows:)*

| Decimal | 3rd Octet Binary |
| :--- | :--- |
| 10.2.**1**.0 | `0000 0001` |
| 10.2.**2**.0 | `0000 0010` |
| 10.2.**3**.0 | `0000 0011` |
| 10.2.**4**.0 | `0000 0100` |

*Observation:* To cover 1 through 4, we must find a bit boundary that encompasses them.
*   The first 5 bits `0000 0` are common.
*   This gives us a `/21` mask (8+8+5).
*   Summary: **10.2.0.0/21** (Mask 255.255.248.0).

### **Advantages**
1.  **Efficiency:** Smaller routing tables = faster lookups.
2.  **Stability:** Flapping links (going up/down rapidly) inside a summarized area do not affect routers outside that area, as the summary route remains valid.
3.  **Traffic Reduction:** Fewer routing updates are sent between routers.
