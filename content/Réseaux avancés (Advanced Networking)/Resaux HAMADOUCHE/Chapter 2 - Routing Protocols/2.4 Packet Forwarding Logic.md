
# 2.4. Packet Forwarding Logic (LPM)

### **The Golden Rule: Longest Prefix Match**
When a router has multiple routes in its table that *could* apply to a destination IP, it **must** choose the most specific one.

**Definition of Specific:** The route with the **longest subnet mask** (the most bits matching the destination IP).

### **Algorithm Logic**
1.  Router receives a packet.
2.  It compares the Destination IP against all entries in the table.
3.  It filters for all entries where the network portion matches.
4.  It selects the entry with the highest CIDR value (e.g., /24 wins over /16).

### **Scenario Example**
**Packet Destination:** `192.168.1.57`

**Routing Table Entries:**
1.  `192.168.0.0 /16` (Matches first 16 bits) -> Broad match.
2.  `192.168.1.0 /24` (Matches first 24 bits) -> Better match.
3.  `192.168.1.48 /28` (Matches first 28 bits) -> **Best Match.**

*   **Logic:**
    *   The destination `...1.57` is `...0011 1001` in binary.
    *   The route `...1.48` covers the range `.48` to `.63`.
    *   Since `.57` falls inside the `/28` range, and `/28` is longer than `/24` or `/16`, the router uses the path associated with **192.168.1.48/28**.

> [!WARNING] **Common Pitfall**
> Students often think the router chooses the path with the best *metric* (speed) first. **FALSE.**
> 1. First, find the **Longest Match**.
> 2. Only if there are *two identical* longest matches (same prefix length) does the router look at **Administrative Distance** or **Metrics**.
